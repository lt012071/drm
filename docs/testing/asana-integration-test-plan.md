# Asana連携機能 動作確認テストプラン

## 前提条件
- システムが http://localhost:3000 で起動済み
- Asana Personal Access Token が設定済み
- ユーザーがログイン済み

## テスト項目

### 1. Asanaセクションの表示確認
- [ ] 日報入力画面にAsanaタスクセクションが表示される
- [ ] 「Asanaタスク」というタイトルが表示される
- [ ] 初期状態では折りたたまれている（矢印アイコンで展開可能）

### 2. ワークスペース取得テスト
- [ ] セクションを展開すると「OWNDAYS」ワークスペースが表示される
- [ ] エラーが発生せずにワークスペースが読み込まれる
- [ ] ローディング状態が適切に表示される

### 3. プロジェクト取得テスト
- [ ] ワークスペース選択後、プロジェクトドロップダウンが表示される
- [ ] 以下のプロジェクトが表示される：
  - Official - 運営・更新
  - Official - Bug
  - Recruit - 運営・更新
  - Official - 新機能
  - その他複数のプロジェクト

### 4. タスク取得テスト
- [ ] 「プロジェクトタスクを取得」ボタンクリックでタスク一覧が表示される
- [ ] 「自分のタスクを取得」ボタンクリックで個人タスクが表示される
- [ ] タスク名、担当者、完了状態が正しく表示される
- [ ] チェックボックスでタスク選択が可能

### 5. タスク変換・追加テスト
- [ ] タスクを選択して「選択したタスクを追加」ボタンをクリック
- [ ] 選択されたタスクが日報のタスク一覧に追加される
- [ ] タスク種別が適切に推測される（会議、開発、その他など）
- [ ] 通知メッセージが表示される

### 6. 前回タスクコピー機能テスト
- [ ] タスク一覧セクションに「前回のタスクをコピー」ボタンが表示される
- [ ] ボタンクリックで前日のタスクがコピーされる
- [ ] 外部連携タスク（Googleカレンダー）は除外される
- [ ] 成功・失敗の通知が適切に表示される

### 7. 統合機能テスト
- [ ] Googleカレンダー + Asana + 手動入力のタスクが混在して表示される
- [ ] 各タスクのソース（Google/Asana/手動）が識別できる
- [ ] すべてのタスクが統計情報に正しく反映される

## エラーハンドリングテスト

### 8. 認証エラー処理
- [ ] Personal Access Token無効時に適切なエラーメッセージ
- [ ] ネットワークエラー時の適切な処理

### 9. データ不在時の処理
- [ ] プロジェクトにタスクがない場合の表示
- [ ] 前日のタスクがない場合の処理

## パフォーマンステスト

### 10. レスポンス時間
- [ ] ワークスペース取得：3秒以内
- [ ] プロジェクト取得：3秒以内  
- [ ] タスク取得：5秒以内

## 期待される結果

### 成功シナリオ
1. ワークスペース「OWNDAYS」が表示される
2. 10以上のプロジェクトが表示される
3. 各プロジェクトから複数のタスクが取得できる
4. 他のメンバーのタスクも表示される
5. タスクが日報に正常に追加される

### データ例
- プロジェクト: "Official - 運営・更新"
- タスク例: "[JP] ゆめりあフェンテ大泉学園店-google権限"
- 担当者: "Kou Keiyou"
- 推測されるタスク種別: "その他" または "定型業務"
